# 资料契约

所有记录均为确定性生成的本地合成资料，不含真实主体信息。不同文件通过标识字段关联；版本、生效时间、缺失状态和回执字段保留原始业务含义。缺失、待审、争议、未回执一律表示**状态未知或处理中**，不能解释成零值或成功。

> 重新生成：`python scripts/generate_data.py`（固定随机种子，行数校验内置）。

## 跨文件约定

1. `orders.policy_version` 与 `config/analysis.json` 的 `policy_windows_days` 对应，构成观察窗口；窗口 + 缓冲期未满的订单计入 `immature_units`，不进入分母。
2. `returns.returned_units` 按订单件数封顶后进入分析；超出部分单独记录为数据质量问题。
3. `return_reviews.reviewed_at` 是修订生效时间。分析只应用 `reviewed_at <= 分析截止日` 的修订，因此同一批资料在不同截止日会得到不同风险，但历史快照不改写。
4. 退款状态 (`refund_state`) 与历史动作 (`actions.csv`) 一经导入即为既成事实；重新分析只更新当前风险和建议，不修改这些记录。
5. 批次追溯完整性由 `lots.traceability_state`、占位批次号、缺失批次号三处共同决定，任一缺失即计为追溯缺口。
6. 所有统计量只使用成熟暴露与已生效修订；未知原因单列，并计入“最坏情况率”，绝不按零处理。
